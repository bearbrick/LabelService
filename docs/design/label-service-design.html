标签生成服务

一个独立部署的 Web 服务。业务人员在网页上拖拽设计标签模板，业务系统用“模板编码 + 数据 JSON”调用接口，拿回 PDF、PNG 或 ZPL 文件。

2026-10-08
状态
待评审
初版重点
绘制一定要方便
性能目标
单张 P95 ≤ 100 ms
  1. 01
    设计模板

    选画布（A4、100×60mm 等预设，或自定义尺寸），拖入文本、图标、图片、一维码、二维码，保存。

  2. 02
    定义字段

    为模板声明字段的 key 和类型，系统自动生成调用方要传的 JSON 样例。

  3. 03
    调用生成

    业务系统提交模板编码和数据，接口直接返回标签文件流，支持批量。

1初版范围

初版要把“设计 → 定义字段 → 调用生成”整条链路跑通，并且让绘制足够顺手。送打印机、发序列号这类和现场强相关的事，先交给调用方。

初版做

  • 网页设计器：7 种元素（文本、一维码、二维码、图片、图标、线、矩形），拖拽、缩放、旋转、吸附对齐、撤销重做
  • 画布预设维护（A4、100×60mm 等）
  • A4 拼版：把做好的单张标签拖到 A4 纸上排版，保存成“版式”；同一个模板既能单张打，也能按版式拼在 A4 上打
  • 字段定义（key + 类型），自动生成 JSON 样例
  • 模板版本：草稿和发布分开，接口只用已发布的版本
  • 开放接口：单张、批量（合并成一个文件或打包 ZIP），输出 PDF、PNG、ZPL（位图模式）
  • API Key 鉴权、调用日志
  • 生成性能：单张服务端处理 P95 ≤ 100 ms，分阶段计时，有监控仪表盘和告警（第 9 节）

初版不做（后续再议）

  • 送打印机：服务只返回文件，打印由调用方负责
  • 发号：序列号、流水号由调用方生成后传入，服务不保存计数，避免重号
  • 模板里嵌套模板（把一个模板作为元素放进另一个模板）
  • 表格元素、按条件显示元素
  • ZPL 原生指令、TSPL 输出
  • 异步批量任务、多租户

2总体架构

服务由网页设计器、管理 API、渲染引擎、开放 API 四部分组成。后端是一个无状态进程，初版单实例部署、数据存 SQLite；以后需要时换成 SQL Server，就可以多实例横向扩展。

技术选型

层选型理由

注意不要把微软雅黑、宋体打包进服务。它们是 Windows 系统字体，授权不允许随意分发。

3数据模型

一个模板有多个版本。每个版本是一份完整的模板 JSON（画布尺寸、字段定义、元素），发布后不再修改。

概念说明
画布预设常用纸张尺寸，如 A4（210×297）、100×100、100×60、80×50、60×40、50×30mm，管理员可以增删。选中预设后把宽高写进模板，之后改预设不影响已有模板
拼版版式A4 等纸张上怎么排多张标签：纸张尺寸、格子尺寸、每个格子的位置和填充顺序、打印偏移。按格子尺寸和模板匹配，同一个模板可以单张打，也可以按版式拼在一张纸上打
模板一种标签，如“成品箱标”。模板编码 templateCode 全局唯一，就是接口里的 key
模板版本编辑产生草稿，发布生成新版本号。接口默认用最新发布版本，也可以指定版本。同一模板同一时间最多一个草稿
元素画布上的一个对象：文本、一维码、二维码、图片、图标、线、矩形
字段模板需要的数据，key + 类型，元素通过 {{key}} 引用
素材上传的图片、图标、字体文件

4标签设计器

目标是像做 PPT 一样画标签：从左边拖进来，在画布上摆好，在右边改属性。常用操作都有快捷键。

元素类型

元素用户能调的说明
文本内容、字体、字号、粗斜体、对齐、换行或自动缩小固定文字和字段可以混写，如 批次：{{batchNo}}
一维码码制、内容、是否显示文字、文字位置Code128、Code39、EAN-13、EAN-8、UPC-A、ITF-14、GS1-128
二维码码制、内容、纠错级别QR、DataMatrix、PDF417；内容可以拼接多个字段
图片来源（素材库或字段）、填充方式、黑白化字段来源只收 base64
图标从图标库选择、颜色内置 GB/T 191 包装储运图示标志（易碎、向上、怕雨等），可上传 SVG
线方向、粗细、虚线横线、竖线
矩形边框粗细、圆角、填充画外框和分区

保证所见即所得

设计器和服务端是两套渲染，必须约束差异：

  • 字体：两边用同一份字体文件，服务端提供字体下载给设计器加载
  • 文本：换行和自动缩小的规则写进规范（第 5 节），两边按同一算法实现
  • 条码：设计器用 bwip-js 预览，服务端用 ZXing.Net 生成，以服务端预览为准
  • 验收：同一模板，设计器和服务端 PNG 的元素位置偏差不超过 0.2mm

A4 拼版

同一个标签模板，既可以单张打（标签机），也可以拼在 A4 不干胶纸上打（激光打印机）。模板本身不变，拼版方式单独保存成“版式”，打印时选择用哪个版式。版式在拼版设计器里画：把已经做好的单张标签拖到纸上，像排模板里的元素一样对齐。

新建版式
选纸张（A4、A5 或自定义），再选一个已发布的模板，格子尺寸取模板的尺寸
拖入
从左侧把模板拖到纸上，生成一个格子；可以拖多次
对齐
和模板设计器一样的网格吸附、对齐参考线、等间距分布；格子之间、格子和纸边都能对齐；方向键微调 0.1mm
自动排列
输入行数、列数、页边距、间距，一键排满，再手动微调
旋转
格子可以旋转 90°，竖着放能多排几张
填充顺序
格子上显示序号，可以按“先行后列”“先列后行”重新编号，也可以手动调整
检查
格子超出纸张或互相重叠时标红，不能保存
打印校准
打一张测试页（格子边框和中心十字），量出打印机的偏差，填写 X、Y 偏移
预览
用样例值预览，或上传一批数据预览多页效果

版式按格子尺寸和模板匹配：一个版式可以给所有同尺寸的模板用，模板详情页列出可用的版式。“把一个模板作为元素放进另一个模板”（模板嵌套）放到二期。

5模板 JSON 规范

模板 JSON 是设计器、数据库和渲染引擎之间唯一的契约。长度一律用毫米，字号用磅（pt），颜色用 #RRGGBB。

  • 坐标原点在标签左上角，x 向右、y 向下；长度保留 1 位小数（0.1mm）
  • rotation 单位是度，顺时针，绕元素中心旋转
  • 元素在 elements 数组里的顺序就是叠放顺序，后面的在上层
  • 数据绑定写 {{key}}；带格式写 {{prodDate:yyyy-MM-dd}}、{{qty:0.00}}（.NET 格式字符串），绑定里的格式优先于字段的默认格式
  • 省略的样式取默认值：字体思源黑体、颜色 #000000、左对齐、垂直居中、不换行、行高 1.2
  • schemaVersion 标记规范版本，以后升级规范时渲染引擎按版本兼容旧模板

元素属性

所有元素都有：id、type、name、x、y、width、height、rotation、locked、hidden。各类型的专有属性：

type专有属性
textcontent；style：fontFamily、fontSize、bold、italic、underline、color、align（left / center / right）、vAlign（top / middle / bottom）、fit（none / wrap / shrink）、minFontSize、lineHeight、letterSpacing
barcodesymbology（code128 / code39 / ean13 / ean8 / upca / itf14 / gs1-128）、value、align、showText、textPosition（bottom / top）、textStyle、minModuleDots、quietZone
qrcodesymbology（qr / datamatrix / pdf417）、value、ecLevel（L / M / Q / H，仅 QR）、quietZone

iconicon（图标库路径）、color
linestroke：width、dash；height 为 0 是横线，width 为 0 是竖线
rectstroke：width、dash；fill、radius

文本排版规则

  • fit: "none"：单行，超出框的部分裁掉
  • fit: "wrap"：在框宽内自动换行（中文按字、英文按单词），超出框高的部分裁掉
  • fit: "shrink"：单行，放不下时自动缩小字号，最小到 minFontSize，还放不下就裁掉
  • 行高 = 字号 × lineHeight

一维码尺寸规则

条码宽度等于“模块数 × 模块宽度”。模块宽度必须是打印机点的整数倍，否则会出现看着正常、扫不出来的情况。

  • 渲染时，模块宽度 = floor(框宽点数 ÷ 模块数) 个点，条码在框内按 align 放置
  • 203dpi 下 1 点 = 0.125mm。模块宽度小于 minModuleDots（默认 2 点）时拒绝生成，返回 BARCODE_TOO_DENSE
  • 内容不符合码制（如 EAN-13 不是 12 或 13 位数字）时返回 BARCODE_INVALID

6数据源定义

每个字段只需定义 key 和类型，其余属性都可选。保存后系统自动生成调用方要传的 JSON 样例。

属性必填说明
key是字母开头，只含字母、数字、下划线；模板内唯一，区分大小写
type是string / number / date / image
name否中文显示名，在设计器的字段列表里显示
required否默认 true，调用时不传就报错
default否调用时不传则用默认值
format否number、date 的默认显示格式
sample否设计器预览和 JSON 样例用

类型与校验

类型调用方传什么校验
string字符串可设最大长度
number数字，或能转成数字的字符串能解析成 decimal
dateISO 8601 字符串，如 2026-10-08、2026-10-08T14:30:00能解析成日期
imagebase64，可带 data:image/png;base64, 前缀PNG 或 JPG，单张不超过 1MB

定义方式

  • 选中模板后进入“数据源定义”页，以表格形式批量编辑字段；设计器左侧的字段面板也能增删
  • 保存时扫描所有 {{key}}：没定义的提示一键添加（默认 string），定义了但没有元素引用的给出提示
  • 字段随模板版本一起发布。已发布版本的字段不会变，调用方不会突然报错
  • 调用时多传的 key 直接忽略，不报错

7渲染引擎

渲染引擎把“模板版本 + 数据”变成文件。PDF 走矢量，PNG 和 ZPL 走位图，三种格式共用同一套排版和绘图代码。

处理流程

  1. 取模板：按 templateCode（和可选的版本号）取已发布版本，内存缓存
  2. 校验数据：必填、类型、格式。批量时先校验全部条目，任何一条不通过就整批返回错误，错误里带条目序号和字段
  3. 替换绑定：把 {{key:format}} 换成实际值
  4. 排版：计算文本换行和缩放、条码矩阵（ZXing.Net 编码），模块宽度对齐打印点
  5. 绘制：SkiaSharp 画到 PDF 文档或位图上
  6. 输出：写入响应流；批量时按要求合并或打包

每一步单独计时，写进调用日志、响应头和监控指标。单张的总预算是 100 ms，各步骤怎么分配见第 9 节。

单位换算

  • 点数 = 毫米 ÷ 25.4 × DPI。203dpi 下 1mm ≈ 8 点，300dpi 下 1mm ≈ 11.8 点
  • 字号：1pt = 1/72 英寸 ≈ 0.353mm
  • DPI 取值顺序：请求参数，其次模板设置，都没有则用 300

输出格式

格式实现适用场景批量
PDFSkiaSharp 矢量输出，嵌入字体子集；条码按 DPI 对齐激光打印机、走打印驱动的标签机、存档合并成多页 PDF，一张标签一页
PNG按 DPI 栅格化；mono=true 时转黑白（文字用阈值，图片用抖动）预览、嵌入其他系统打包 ZIP
ZPL整张标签栅格化成黑白位图，用 ^GFA 指令输出斑马等支持 ZPL 的标签机直接打印多个 ^XA…^XZ 拼成一个文件

ZPL 用位图模式，是因为中文字体和图片不需要打印机支持，效果和 PNG 一致；代价是文件比原生指令大，传输稍慢。原生 ZPL 指令（^FD、^BC）放到二期。

拼版渲染

  • 按版式的格子顺序依次放标签：每个格子先把画布平移、旋转到格子位置，再按单张的方式排版和绘制；一页排满换下一页
  • 只支持 PDF 和 PNG：PDF 一页对应一张纸，PNG 每页一张图（多页时打包 ZIP）。ZPL 面向热敏标签机，不支持拼版
  • 模板里不随数据变化的内容（Logo、固定文字、边框）每页只计算一次，在各格子重复使用
  • 整页加上版式的打印偏移；可以选择画出格子边框，在白纸上打印时当裁切线

字体

  • 服务启动时加载 fonts/ 目录下的字体文件，按 fontFamily 名称匹配
  • 模板引用了不存在的字体时，降级到思源黑体，并在响应头 X-Label-Warnings 里提示
  • 同一份字体文件通过 /fonts/{name} 提供给设计器加载

8开放接口

业务系统只需要一个 API Key 和两个接口：单张生成、批量生成。成功时直接返回文件流，失败时返回 JSON 错误。

鉴权

  • 请求头 X-Api-Key。Key 在管理后台按调用系统发放，数据库只存哈希
  • 可选请求头 X-Request-Id：调用方生成的请求号，服务端原样写进调用日志，双方对账用；SDK 会自动带上
  • 每个响应都带 Server-Timing 头，列出服务端各阶段耗时（毫秒），调用方可以据此区分网络耗时和服务端耗时
  • 可以限制每个 Key 能用哪些模板；全程 HTTPS
  • 设计器和管理 API 用登录态：初版内置账号 + JWT，后续对接公司统一登录

9生成性能与监控

生成速度是这个服务的核心指标：单张标签从服务端收到请求到返回最后一个字节，P95 不超过 100 ms。每个请求分阶段计时，指标进监控，变慢时自动告警。

性能指标

单张标签（≤ 100×150 mm，≤ 300 dpi，PNG / ZPL / PDF）P95 ≤ 100 ms，P99 ≤ 200 ms服务端处理时间：收到完整请求到写完最后一个字节。核心指标，必须达标
单张标签，局域网内调用方实测P95 ≤ 150 ms包含网络往返。SDK 同时给出总耗时和服务端耗时，方便区分

单张 100 ms 怎么分配

怎么做到

  1. 热路径不碰数据库：模板按“编码 + 版本”预编译成排版对象，缓存在内存；发布新版本时预热。API Key 校验查内存里的哈希表。
  2. 启动预热：加载全部字体、图标和素材，并用样例值把每个已发布模板各渲染一次，第一次调用不慢。
  3. 对象复用：字体、画笔、字形测量结果都缓存；缓冲区用 ArrayPool，避免频繁分配大对象。
  4. 条码编码缓存：同一内容的条码矩阵直接复用，批量里公共字段的条码只编码一次。
  5. 输出编码选快的参数：PNG 用低压缩等级，以体积换速度；ZPL 位图按行查表打包；PDF 的字体子集按模板版本缓存。
  6. 流式返回：生成完直接写响应流，不落盘、不二次复制。
  7. 图片字段：base64 不超过 1 MB，解码后按目标尺寸缩放并缓存。
  8. 并发控制：渲染并发数等于 CPU 核数，多出的请求排队；排队超过 2 秒返回 503，避免所有请求一起变慢。
  9. 运行时：开启 .NET Server GC 和 ReadyToRun 预编译，减少冷启动和 GC 停顿。

监控

服务用 .NET 自带的指标和链路 API（OpenTelemetry 标准）采集，导出到 Prometheus，用 Grafana 看仪表盘，也可以接公司现有的监控平台。管理后台的“工作台”同步显示今日 P95、慢调用数和最慢的模板。

指标维度用途
label_render_duration_ms（直方图）接口、模板、格式、DPI、结果P50 / P95 / P99，判断是否达标

每个响应都带 Server-Timing 头，列出各阶段耗时；调用日志也记录总耗时、各阶段耗时和模板版本。单张超过 100 ms 的请求在调用日志里标记为慢调用，可以单独筛选。服务另外提供 /health（存活和就绪检查）和 /metrics（Prometheus 抓取）。

压测与防退化

  • 基准测试：用 BenchmarkDotNet 对每个示例模板的渲染流水线做基准。CI 每次提交都跑，单张中位数比基线慢 20% 以上就不允许合并。
  • 压测：用 k6 或 NBomber 在目标机器（4 核 8 GB）上压单张接口，50 并发时 P95 ≤ 100 ms、错误率为 0。结果写进每次发布的记录。
  • 发布前检查：模板发布时用样例值实际渲染一次并计时，超过 50 ms 就提示设计者，常见原因是大图片、600 dpi 和 A4 满版。只提示，不阻止发布。

其他非功能需求

  • 部署：初版单实例（Docker 或 Windows 服务），前期不考虑高可用；服务本身无状态，以后换 SQL Server 后可以多实例，届时模板缓存最长 60 秒过期。批量生成 PNG 或 ZIP 时并行渲染，PDF 按页顺序写入。
  • 安全：API Key 只存哈希；请求体上限 20 MB；图片字段只收 base64，不支持传 URL，防止服务器被利用去访问内网地址；上传素材校验类型和大小，SVG 上传时清除脚本；管理操作需要登录，模板发布记录操作人。
  • 日志与审计：每次生成写一条调用日志（调用方、模板、版本、格式、张数、总耗时、各阶段耗时、结果）；不存业务数据全文，需要补打时由调用方重新调用；模板每次发布都保留版本，可以查看和回滚。

用法

// 应用内共用一个实例
var client = new LabelServiceClient(new LabelServiceClientOptions
{
    BaseAddress = new Uri("https://label.example.com/"),
    ApiKey = ConfigurationManager.AppSettings["LabelApiKey"],
});

// 单张：生成 PDF 并保存
var request = new RenderRequest("BOX_LABEL", LabelFormat.Pdf)
    .Set("partName", "电源适配器")
    .Set("qty", 50)
    .Set("prodDate", DateTime.Today)
    .Set("boxNo", "C2610080001");
LabelFile file = await client.RenderAsync(request);
file.Save(Path.Combine(@"D:\Labels", file.FileName));
// 批量：一个 ZPL 文件直接发给斑马打印机
var batch = new BatchRenderRequest("BOX_LABEL", LabelFormat.Zpl)
    .SetCommon("partName", "电源适配器")
    .SetCommon("batchNo", "20261008-A");
foreach (var boxNo in boxNumbers)
    batch.AddItem().Set("boxNo", boxNo);

LabelFile zpl = await client.RenderBatchAsync(batch);
await NetworkPrinter.SendAsync("192.168.1.50", 9100, zpl.Content);
// 错误处理
try
{
    LabelFile file = await client.RenderBatchAsync(batch);
}
catch (LabelServiceException ex) when (ex.ErrorCode == LabelErrorCodes.FieldRequired)
{
    foreach (var e in ex.Errors)            // 第几条、哪个字段
        log.Warn($"第 {e.Index + 1} 条缺少 {e.Field}");
}
catch (LabelServiceException ex) when (ex.IsTransient)
{
    // 网络或服务暂时不可用，SDK 已经重试过；稍后再试，或者转人工补打
}

行为约定

  • 线程安全：一个 LabelServiceClient 可以多线程共享，建议应用内单例。内部复用 HttpClient，避免连接和端口耗尽。
  • 同步方法：Render 等同步方法内部用 Task.Run 等待，在 WinForms 界面线程里调用不会死锁，但会卡住界面；界面代码建议用 async 版本。
  • 超时与重试：单次请求默认 30 秒超时。网络错误、超时和 502、503、504 自动重试 2 次，间隔 0.5 秒、1 秒；其余 4xx 和 500 不重试。
  • 本地预校验：模板编码为空、份数不在 1–100、批量总张数超过 500、PNG 批量没用 Zip 时，直接抛 ArgumentException，不发请求。
  • 值转换：DateTime 转 ISO 8601（只有日期时转成 yyyy-MM-dd），byte[] 转 base64（图片字段），枚举转字符串，值为 null 的字段不发送。
  • 请求头：自动带 X-Api-Key、User-Agent（LabelService.Client/版本号）和 X-Request-Id（每次调用一个 GUID）。服务端把 X-Request-Id 写进调用日志，双方对账用。
  • 日志：每次调用结束触发 CallCompleted 事件，给出操作、模板、状态码、错误码、总耗时、服务端耗时（来自 Server-Timing）、尝试次数、requestId 和 traceId。
  • 性能：SDK 自身的序列化和解析开销控制在 1 ms 以内；复用 HTTP 长连接，不在每次调用时重新握手。所以要求应用内只建一个客户端实例。

项目做法
发布形式公司私有 NuGet 源上的 LabelService.Client 包；不用 NuGet 的厂商发 zip，里面有 DLL、XML 注释、README 和演示程序源码

测试环境给三方一个测试环境地址和 lbl_test_ 开头的测试 Key，测试环境的模板和生产隔离

验收标准

  • 在只装了 .NET Framework 4.8 的 Windows 10 上，双击演示程序能打开；勾选模拟服务后能生成单张和批量标签。
  • 连上测试环境后，三种格式都能生成；ZPL 通过 9100 端口在斑马打印机上打出来，条码能扫。
  • 缺必填字段、Key 无效、模板未发布、批量超量时，界面显示的错误码和第 8 节一致。
  • 勾选“模拟网络抖动”时，调用日志里能看到重试 1 次后成功。
  • “调用代码”页签里的代码，复制到新建的 .NET Framework 4.8 和 .NET 10 项目里都能编译通过。

### 2026-10-11 · Claude

**怎么查的**：在浏览器里对 20 个页面和 22 个弹窗、抽屉逐个打开后量 DOM，查五类问题：页面横向滚动、文字被裁掉且没有悬停提示、下拉框文字被截断、内容被纵向裁掉或超出窗口、文字和控件互相重叠（量的时候扣掉滚动容器裁掉的部分，避免误报）。尺寸：1920×1080、1440×900、1280×720、1100×700（另加 1101×700，设计器在 1100px 及以下显示“窗口太窄”）、768×900。演示程序用 PrintWindow 在默认尺寸、最小尺寸（960×600）、最大化各截一张。

**发现并修好的问题**：

- 长名称：模板树、模板卡片和列表、工作台的柱状列表、顶栏的业务切换按钮，名称太长时撑破布局或被截断没有提示。改成省略号加悬停提示；顶栏业务名称限宽 220px（1280 宽时原来会把右侧菜单挤出窗口 3px）。模板卡片最小列宽改为 280px。
- 数据源页签：字段表和右侧说明并排时表格列被挤窄，改为 1680px 以下上下排列。
- 拼版设计器：左栏内容多时不能滚动（样式优先级被 `.panel { overflow: hidden }` 盖住）；窗口较窄时工具栏右侧的网格、缩放按钮和左侧按钮重叠，改为整组换行靠右，提示框不再伸出窗口。
- 设计器在 1100px 以下显示“窗口太窄”的提示时，被盖住的工具栏仍然撑出 9px 横向滚动条、还能用 Tab 键切到看不见的按钮；改为提示下面的内容不参与显示。
- 带单位的数字输入框（如画布宽高）：浏览器自带的上下箭头盖住数字，去掉箭头。
- 窗口变化：1100～1440px 宽时模板树占掉 280px，设计器画布只剩 199px（1101 宽）到 378px（1280 宽）。改为窗口窄于 1440px 时打开设计器、或窗口从宽变窄时自动收起模板树（面包屑前的按钮可以再展开，用户手动展开后不会被反复收起）；拼版设计器也加了同样的按钮。1101 宽时画布变成 479px，1280 宽时 658px。新组件 `components/admin/NavToggle.vue`。
- 窗口变化：画布适应窗口后再改变窗口大小，缩放比例不变，纸张会被裁掉（1920 适应到 279%，缩到 1280 后仍 279%）。改为视图停在“适应窗口”时跟着重新适应，手动缩放或平移过就保持；模板设计器（`stageViewport.ts`）和拼版设计器（`sheetStage.ts`，右下角的比例同步更新）都改了。
- 演示程序：最小尺寸 960×600 时字段表格被压得只剩表头；“必填”表头被截成“必”、number 被截成“num...”。字段、名称、类型、必填四列按内容定宽；左栏放进可以上下滚动的外框，最小高度保证表格显示 6 行（不用 Dock 加 AutoScroll，那样出现纵向滚动条后还会多出横向滚动条）。

**复验**：修完后 5 种尺寸下 20 个页面都是 0 个问题，22 个弹窗在 1920、1440、1280、1100、768 下都是 0 个问题；设计器和拼版设计器的画布、标尺在 1920→1280→1101 之间变化时跟着容器走。演示程序 net48、net10.0-windows 的 `--smoke` 都通过，最小尺寸和最大化截图正常。截图和完整结果见 `docs/reviews/t025-evidence/`。`npm run check`、`npm run build`、`verify.ps1` 全量通过。

**范围补充**：为了窗口变化时画布重新适应，改了 `editor/stageViewport.ts`、`editor/sheetStage.ts`（只加了“停在适应窗口状态”的标记，不影响其他行为）；`stores/dialogs.ts` 只改了一行注释；截图放在 `docs/reviews/t025-evidence/`；review 第 6 节补了“高缩放下的演示程序”，第 7 节补了第 8 条（自动收起模板树要用户认可）。

**没做 / 留给下一位**：

- 没法在本机改 Windows 的显示缩放（系统设置不能动），所以 125%、150% 缩放下的演示程序没验证。演示程序没有设置 AutoScaleMode，标签列宽 76px、标题栏高 44px、左栏宽 440px 是固定像素，高缩放下可能显得挤，建议在有高缩放屏幕的机器上看一眼。
- 网页的浏览器缩放（Ctrl+加号）等价于更窄的窗口，已由上面几个宽度覆盖。
- 模板树里很长的模板名称是换行显示，没有改成省略号（悬停也能看完整名称和编码）。

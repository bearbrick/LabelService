## 目标

用户在 150% 缩放的屏幕上测试演示程序，提了三个问题：

1. 显示不全：“服务地址”“模板编码”“超时（秒）”等标签折成两行，DPI 下拉框只显示“模板默”。原因是窗口按 96 DPI 的像素写死了宽度，高分屏上字变大、宽度没变。
2. 模板编码怎么刷新：下拉框里只写死了两个示例模板。
3. 批量生成不要“递增字段”：批量要几张就由调用方传几组完整的数据，责任在调用方，演示程序要照这个用法演示。

## 验收标准

- [ ] 150% 缩放下左栏的标签不折行、下拉框文字完整，窗口按屏幕缩放（AutoScaleMode.Dpi），太大时不超出工作区
- [ ] 模板编码旁边有“刷新”：用 `ListTemplatesAsync` 列出这把 Key 能用的模板，下拉列表同时显示名称和尺寸；启动时、测试连接成功后、切换模拟服务时自动刷新；选中模板自动读取字段
- [ ] “模板与数据”分成“单张数据”（一个字段一行）和“批量数据”（一行一张标签，列是全部字段）；批量数据可以加行、删行、清空、从 Excel 复制粘贴（带表头时按表头对列）；必填为空标红
- [ ] 批量生成按批量数据的行数，每条用 `AddItem().Set(...)` 给全数据，不再有“批量条数”“递增字段”；调用代码的批量写法同样每条给全
- [ ] 内置模拟服务支持 `GET /api/v1/templates`
- [ ] 自检（`--smoke`）覆盖刷新模板、批量数据、粘贴、标签不折行，模拟服务和真实服务都通过
- [ ] `verify.ps1` 通过（见 AGENTS.md）
- [ ] 相关文档已更新

## 不做

- 批量里每条单独的份数（SDK 支持 `AddItem(copies)`，演示程序先不放这一列）
- 原型 `docs/prototypes/label-sdk-demo-prototype.html` 里的“递增字段”不改（原型是评审时的交互稿，改设计书功能表即可）

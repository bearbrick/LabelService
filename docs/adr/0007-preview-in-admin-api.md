# 0007 服务端预览放在管理接口 `/api/admin/preview`，字体通过 `/fonts` 公开提供

状态：已采纳（2026-10-11 用户确认）
日期：2026-10-09
关联：T-016、ADR 0006

## 背景

设计书第 8 节把服务端预览列在开放接口里：`POST /api/v1/preview`，“设计器用，需要登录”。后来 ADR 0006（已采纳）定了管理接口和开放接口的鉴权互不相通：开放接口只认 `X-Api-Key`，登录令牌只在 `/api/admin` 有效，T-014 的验收标准也要求“登录态不能调开放接口”。这样“`/api/v1` 下需要登录的接口”就和 ADR 0006 冲突了。

另外，设计器要加载服务端的字体文件。浏览器的 `@font-face` 请求不能带 `Authorization` 头，字体接口没法要求登录令牌。

## 决定

- 服务端预览实现为管理接口 `POST /api/admin/preview`，权限点 `tpl.view`。请求体 `{ template, data?, dpi?, mono? }`，模板不经过存储，直接检查后渲染成 PNG；不写调用日志；指标只记 `endpoint=preview` 的请求数和总耗时。
- `/api/v1/preview` 暂时保留 501，消息指向新地址；本 ADR 采纳后从开放接口和设计书第 8 节的接口列表里删掉（它从来没实现过，没有调用方）。
- 字体：`GET /fonts/fonts.css` 和 `GET /fonts/{文件名}` 不需要登录（思源黑体、思源宋体是 SIL OFL 授权，可以公开分发），只提供已加载的字体文件。`fonts.css` 用 `ascent-override`、`descent-override` 把浏览器的字体度量设成服务端排版用的值。

## 备选方案

- **`/api/v1/preview` 同时认登录令牌**：要在开放接口的鉴权里加一条特例，破坏 ADR 0006 的隔离，开放接口的指标和日志也要区分来源。
- **预览用 API Key**：设计器要拿一把 Key，Key 会出现在浏览器里，不安全。
- **字体走管理接口、前端用 fetch 下载再 `new FontFace()`**：能带令牌，但字体本来就可以公开，徒增复杂度；也不能利用浏览器的缓存。

## 影响

- 设计书第 8 节接口列表、`docs/contracts.md` 第 2 节里的 `/api/v1/preview` 要改（采纳后改）。
- `docs/admin-api.md` 新增预览接口。
- 部署（T-017）时 `/fonts` 要和 `/api` 一样转给服务端。

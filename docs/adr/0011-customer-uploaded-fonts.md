# 0011 字体由客户上传，发布包不再带字体

状态：已采纳（2026-10-11 用户提出：“字体希望可以通过外部上传使用，分发时不会有版权问题，让客户自己传字体上来”）；“发布包不带字体”这一条待用户确认（review 第 7 节）
日期：2026-10-12
关联：T-028、ADR 0001（技术选型）、AGENTS.md R7

## 背景

渲染用的字体原来只来自部署目录 `fonts/`：构建时从 `backend/assets/fonts` 复制进输出目录和发布包，服务启动时一次性加载，运行中不能增减。设计器只提供思源黑体、思源宋体两种。

产品要卖给客户时，字体随包分发有两个问题：一是授权，思源黑体、思源宋体（SIL OFL）可以随包分发，但客户常常要用自己买了授权的字体（公司标准字、方正、汉仪等），这些我们不能分发；二是一致性，客户只能用我们给的两种字体，想用别的就得改部署目录、重启服务，设计器里也选不到。

## 决定

- 管理后台“素材与字体”页可以上传字体（`.ttf`、`.otf`、`.ttc`、`.otc`，单个不超过 50 MB），放在数据目录的 `fonts/` 下（和上传的素材、Logo 一样跟着数据目录备份和迁移）；上传后立即生效，不用重启。可以删除上传的字体；部署目录里的字体只读。
- 模板里的 `fontFamily` 本来就是字体名（找不到时降级到默认字体并给 `FONT_FALLBACK` 警告），所以模板格式不变：上传的字体按字体文件里的家族名使用，设计器的字体下拉框列出服务端已有的全部字体。思源黑体、思源宋体仍然用模板名 `SourceHanSansSC`、`SourceHanSerifSC`（别名照旧）。
- 默认字体还是思源黑体（`SourceHanSansSC`）。新装的服务没有字体时，页面提示上传思源黑体（Noto Sans SC，SIL OFL，可免费商用）。
- 发布包（`dotnet publish`、Docker 镜像）不再带字体文件；开发和检查程序照旧从 `backend/assets/fonts` 复制到输出目录。已有部署升级时，原来部署目录里的字体继续可用。
- 字体授权由上传的人负责：上传界面写明“请确认字体授权允许在服务器上使用和嵌入生成的 PDF”。

## 备选方案

- **继续只在部署目录放字体**：要登录服务器、重启服务，客户自己做不了；设计器也选不到新字体。
- **字体存数据库**：CJK 字体动辄十几、几十 MB，放进库里备份和迁移都慢；和素材一样放数据目录更一致。
- **上传后重启服务生效**：简单，但会中断正在用的接口。改成运行中重新加载：字体注册表换成新的一份，正在渲染的请求继续用旧的一份，旧的那份等服务退出时再释放（上传、删除很少，内存多占一点可以接受）。

## 影响

- 渲染引擎的 `FontRegistry` 增加“重新加载”：内部换成整份替换的快照，渲染时取一次当前快照，热路径只多一次读引用。上传的字体整份读进内存（不占文件，删除时 Windows 上不会因为文件被占用删不掉）。
- `/fonts/fonts.css` 列出全部字体（不只是思源黑体、思源宋体），设计器和服务端用同一份字体文件。
- 上传、删除字体记操作日志（类型“字体”），权限点沿用 `res.manage`。
- AGENTS.md R7 不变（仍然不打包微软雅黑、宋体等系统字体）；客户上传自己有授权的字体不受这条限制。

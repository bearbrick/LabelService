# 0012 字段的自动值：调用方不传时由服务端算出来

状态：已采纳（2026-10-12 用户提出：“根据数据类型整点可以用的默认值，比如获取当前时间，这样有些就不需要接口传递了，参考常用的预设一些”）
日期：2026-10-12
关联：T-038、`docs/contracts.md` 第 1 节、设计书第 6 节

## 背景

字段原来只有固定的默认值（`default`）。标签上很多值其实不用业务系统传：打印日期、有效期（今天加 N 天）、批量里的“第 3 箱 / 共 20 箱”、哪个系统打的。让每个调用方都自己算一遍，既重复又容易不一致（比如各系统的时区、有效期算法不同）。

## 决定

- 模板字段加一个可选属性 `auto`（自动值），只认下面这些写法，和字段类型对应：

  | 类型 | `auto` | 含义 |
  | --- | --- | --- |
  | date | `today` | 当前日期 |
  | date | `now` | 当前日期和时间（到秒） |
  | date | `today+30d`、`today-1d`、`today+6m`、`today+1y` | 今天加减 N 天、月、年（N 为 1～9999；加月、加年遇到月底取当月最后一天） |
  | number | `index` | 这一张在本次请求里是第几条（从 1 开始；同一条的多份是同一个序号） |
  | number | `total` | 本次请求一共几条 |
  | string | `client` | 调用方名称（管理后台“调用方与密钥”里的名称） |
  | string | `requestId` | 这次调用的请求号（X-Request-Id；没带时是服务端的跟踪号，和响应头 X-Trace-Id 一样） |

- 取值顺序：调用方传的值 → 批量公共字段 → 自动值 → 固定默认值（`default`）。调用方传了就用传的，自动值只在没传时补上。
- 同一次请求里的“当前时间”只取一次，批量里每张都一样。
- 时间按服务端配置的时区：`LabelService:Render:TimeZone`（如 `Asia/Shanghai`、`China Standard Time`），不配时用服务器本机时区。Docker 容器默认是 UTC，部署说明里要求配置。
- 有自动值的字段不用传：设计器选了自动值时把“必填”取消；字段定义接口（`/schema`）返回 `auto`，调用样例里不放这些字段（照着样例传反而会盖掉自动值）。
- 发布前检查不认识的写法、和类型不匹配的写法（比如 number 字段写 `today`）。

## 备选方案

- **在 `default` 里写特殊字符串（如 `=today`）**：和真的想用这个字符串当默认值的情况冲突，类型也不好校验。
- **任意表达式（`today + 30`、`concat(...)`）**：灵活但要做解析和沙箱，出错难查；先用固定的几种写法，够用再说。
- **流水号（跨请求递增）**：要在服务端存计数、处理并发和多实例，和“开放接口不访问数据库”（R3）冲突；业务系统自己的单号更可靠。

## 影响

- 契约：`FieldDefinition` 多一个可选属性 `auto`，旧模板不受影响（向后兼容，不升 `schemaVersion`）。前端 `template.ts`、SDK 的 `TemplateField` 同步加上。
- 渲染引擎 `FieldValidator` 多一个可选的自动值上下文（当前时间、总条数、调用方、请求号），热路径只在字段有 `auto` 且没传时多算一次。
- 设计器“数据源”页的默认值一栏改成“固定值 / 自动值”二选一，自动值按类型给出上面的预设。

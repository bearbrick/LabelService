## 2. 权限

逐个看了 `Server/Admin/*.cs` 的全部路由（除 `/login` 外都要求登录，`RequireAdmin(权限点)` 在过滤器里每次从库里读用户，停用、改角色立即生效）和开放接口（API Key + IP 白名单 + 按业务分组授权，单张、批量、schema 三个接口都查 `CanUse`）。

| 发现 | 严重度 | 处理 |
| --- | --- | --- |
| 调用方管理不看业务范围：业务范围受限、有 `api.manage` 的用户（如内置“接口运维”角色）能新建“全部业务”的调用方，或重置全部业务调用方的 Key 并拿到新 Key，从开放接口调用别的业务的模板 | 高 | **已修复**（e431d3e、758d1ef）：范围受限的用户只能看到、修改、启停、重置授权完全在自己范围里的调用方（否则 404），只能授权自己范围里的分组、不能授权全部业务（否则 403）；前端禁用“全部业务”勾选。检查 `ClientScopeChecks` 5 项，去掉保护后失败（`client-scope.txt`） |
| `sys.user` 等同管理员：有这个权限点的人能重置任何用户（包括系统管理员）的密码并拿到临时密码，能给自己新建的用户分配“系统管理员”角色，能把自己的业务范围改成全部；`sys.role` 能给自己的角色加任何权限点 | 中（内置角色里只有系统管理员有这两个权限点；自定义角色时才会暴露） | **需要用户决定**（见第 7 节），没有改：这是权限模型的取舍，ADR 0006 没写 |
| 操作日志 `/op-logs` 不按业务范围过滤（调用日志、工作台是过滤的） | 低 | 记录；要不要过滤需要决定 |
| `/layouts/test-page` 只要登录（画格子边框的校准页，不含模板数据）；`/roles`、`/layouts` 列表只要登录 | 低 | 按设计，记录 |
| 开放接口对有效 Key 区分“模板不存在 404”和“无权 403”，能探测模板编码是否存在 | 低 | 按设计书的错误码，记录 |

其他确认过没有问题的：登录失败锁定、首次登录强制改密码、密码哈希、JWT 签名密钥不提交（`admin-signing.key` 在数据目录）、配置里只存 API Key 的 SHA-256、素材 SVG 清洗、图片只收 base64 且限 1 MB、请求体大小上限。

## 3. 错误处理

- 渲染（R6）：调用方能修正的问题抛 `LabelRenderException(错误码)` 返回 400；其他异常在单张、批量接口统一记错误日志并返回 `RENDER_FAILED`（带 traceId），没有包装成 400，也没有吞掉。`OperationCanceledException` 不拦。
- 计时：客户端中途断开时调用日志记 `aborted`（T-021 新增），不会把没写完的响应记成成功。
- 数据库升级：失败时恢复备份、写 Critical 日志、抛异常让服务不启动（修复前会留下半迁移的库，重试报 duplicate column）。
- 调用日志在后台批量写；写入失败记警告日志并丢弃这一批，不影响接口返回（`RenderLogService` 只拦数据库相关异常）。队列满丢弃的条数进指标 `label_log_dropped_total`，但写库失败丢弃的那一批只有警告日志、不进这个指标，属可以改进的地方。
- 每日备份失败只拦 IO / SQLite / 权限异常并记日志。
- 没发现吞掉程序缺陷的 `catch`：后端全部带 `when` 过滤或重新抛出；SDK 的 `CallCompleted` 事件故意吞掉调用方自己的处理函数抛的异常（写 Trace 警告，保证不影响调用结果），这是设计如此。

## 5. 测试有效性

| 发现 | 处理 |
| --- | --- |
| 基准门禁 fail-open：结果为空时循环一次都不进，直接“通过” | 修复，并加 `--self-test`；用错误过滤、模拟构建失败两种办法确认退出码 3 |
| 原来的 ToUnicode 检查只看“成”“品”和数字有映射，看不出部首问题 | 加了对“日”“寸”“毛”和部首区的检查；去掉修复后失败 |
| 计时没有独立验证（同一份计时既写头又写日志，测不出差别） | 新增 `TimingChecks`：客户端拿到头后停 800 ms 再读；修复前失败 |
| 旧库升级只测了“从空库建”，没测“从旧版本升级”和“中途失败” | 新增 `UpgradeChecks`（真实的旧结构 + 故障注入）；去掉保护后失败 |
| 调用方授权检查只用全部业务的 admin，测不出范围问题 | 新增 `ClientScopeChecks`；去掉保护后失败 |
| 新的 PNG 编码 | `PngChecks` 用独立解码器逐像素对比；把灰度通道改坏 1 个最低位就失败 |
| 压测脚本默认是“固定 60 次/秒”，不是验收要求的“50 并发持续压” | `single.js` 默认改成 50 个并发持续 60 秒，同时卡 Server-Timing 和 k6 自己的 P95；到最后一个字节的分位数用 `log-report.cs` 从调用日志算 |
| 前端只有纯逻辑模块的检查（69 项），组件和画布交互没有自动化测试 | 记录：靠浏览器手工复核，以后可以考虑 Playwright（新依赖要 ADR） |
| 同一台笔记本上基准有 ±4%～±12% 的波动（温度、负载） | 门禁按 20% 判；PDF、ZPL 各项这次 +2%～+12%，没改这些代码，属波动 |

## 7. 需要用户决定的最小问题

1. ~~ADR 0007~~：**已决定**（2026-10-11）：采纳，预览只在管理接口，`/fonts` 公开（T-022）。
2. ~~ADR 0009~~：**已决定**（2026-10-11）：采纳，监控自建 Prometheus + Grafana；告警发到哪个群还没定（T-022）。
3. **`sys.user` / `sys.role` 的权限边界**：维持“等同管理员”（只给信得过的人），还是加限制（不能分配比自己大的角色、不能重置系统管理员密码、不能改自己的业务范围、授出的业务范围不超过自己）？
4. **旧库升级的换算方式**：现在为保证每个调用方的可用模板一个不多一个不少，同一分类可能拆成几个分组（“包装”“包装（2）”）；如果更想按分类一对一建分组（部分调用方权限会变宽或变窄），需要说明。
5. **T-018 的两个补充**：`START_SLOT_INVALID` 错误码、裁切线放在版式里（而不是请求参数），是否认可？

8. **设计器自动收起模板树**（T-025）：窗口窄于 1440px 时打开设计器（或窗口从宽变窄）会自动收起左侧模板树，给画布留出宽度（1280 宽时画布从 378px 变成 658px），面包屑前的按钮可以再展开。是否认可，还是保持原来“只手动收起”？

## 8. 依赖和安全备注

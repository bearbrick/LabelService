## 可回滚的操作步骤（本轮没有向原目录执行）

1. 等原任务停止写入并形成稳定提交；记录其分支和 SHA、`git status --porcelain`，确认干净。备份手测数据、未跟踪/忽略内容，尤其原来被 logs/ 规则忽略但构建依赖的十个源码。不要仅凭 Git 干净就省略这些备份。
2. 在**新的评审目录**从该稳定原提交克隆，创建兼容评审分支，fetch 本次候选分支，然后 `git merge --no-ff --no-commit <本次候选确切 SHA>`。所有编辑/冲突解决仅在评审目录，按上表保留品牌结构和两个 CSS 导入，不能对 TopBar/main.ts 整文件采用 ours/theirs。
3. 在该评审目录提交兼容合并，执行统一完整验证和上表受影响布局回归；保留合并前稳定 SHA 与两父节点的合并提交 SHA。失败时只放弃该评审分支或 `git merge --abort`（尚未提交时），原目录不受影响。
4. 审定可应用时，再核对原目录 HEAD 仍是步骤 1 的稳定 SHA、干净且无活跃写入；先建备份分支，再 fetch 已验证兼容分支，`git merge --ff-only <已验证兼容合并 SHA>`。这样兼容提交以原新功能稳定提交为第一父节点，保留新品牌和所有该时点功能。条件变化时重新评审，不强推或硬重置。
5. 需回滚时，先在新的回滚评审克隆预演 `git revert -m 1 <兼容合并 SHA>` 并验证，再审定应用该回滚提交。第一父节点是新功能稳定版本，因此回滚的是页面兼容整合，保留当时原新功能。忽略源码/数据的备份单独保留，代码回滚不自动替代数据；不要在运行中的原目录执行硬重置。

仅撤销本次分段补丁时，可在本隔离分支 `git revert a6d16d7`，即回到 9689073 的分段 CSS 行为。该办法用于隔离候选，不应在已自行包含 bf911ff 的原分支盲目重复撤销。

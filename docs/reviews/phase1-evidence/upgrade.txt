# 旧库升级：数据换算、迁移前备份、失败恢复（T-021）

检查：backend/tests/LabelService.Backend.Checks/UpgradeChecks.cs。旧库按 AddApiClients 迁移时的结构建（模板有 category，调用方有 allowed_templates），调用方 MES 是 *、WMS 是 BOX_LABEL、ERP 是 BOX2、A4_SHIPPING_MARK、GONE（GONE 库里不存在）。
故障注入：用自己的 DbContext 拦截命令，在迁移执行 PRAGMA foreign_keys = 0 之后抛异常（验收报告里“中途失败后重试报 duplicate column”的位置）。
实现：Server/Data/DatabaseUpgrade.cs（有待执行迁移时先 VACUUM INTO 备份到 data/backups/，失败就用备份覆盖库文件并拒绝启动）、Server/Data/LegacyUpgrade.cs（迁移前读出分类和授权，迁移后按“分类 + 能用的调用方集合”建业务分组，逐个调用方换算授权）。

## 换算规则说明（需要用户确认的选择）
- 原来按模板编码授权，现在按业务分组授权（ADR 0006）。为了让每个调用方升级后能用的模板一个不多一个不少，同一分类里“能用的调用方集合”不同的模板拆成不同的分组（“包装”“包装（2）”），没有分类的进“未分组”，编码 LEGACY_n；* 换成“全部业务”。
- 授权里写了、库里已经不存在的模板编码（如 GONE）没法换算，写一条警告日志。
- 另一种做法是按分类一对一建分组、接受部分调用方权限变宽或变窄；如果更想要这种，需要用户决定。
